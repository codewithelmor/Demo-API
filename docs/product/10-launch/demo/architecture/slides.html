public sealed class CreateProductEndpoint
    : Endpoint<CreateProductRequest, ProductResponse>
{
    public override void Configure()
    {
        Post("/products");
        Policies(AuthPolicies.AdminOnly);
        Summary(s => { s.Summary = "Create a product"; ... });
    }

    public override async Task HandleAsync(
        CreateProductRequest r, CancellationToken ct) =>
        await Send.ResultAsync((await new CreateProductCommand(
            r.Name, r.Sku, r.Description, r.Price, r.StockQuantity)
            .ExecuteAsync(ct)).ToCreated(HttpContext));
}

API · DATA

PostgreSQL 18: EF Core writes, Dapper reads

Two tools, clear roles

  • EF Core: all writes, migrations, Identity
  • Dapper: views, report functions, one procedure
  • EF migrations own every schema object
  • Dates timestamptz UTC; money numeric(12,2)

Never delete rows

  • Soft delete via interceptor + query filters
  • App DB role has no DELETE privilege
  • Audit row written in the same transaction
  • [PersonalData] values never audited

Concurrency by design

  • ETag from xmin; PUT needs If-Match
  • 428 if missing, 412 if stale
  • SELECT … FOR UPDATE in product ID order
  • No deadlocks by construction

API · SECURITY & RESILIENCE

Own JWT issuer, deny by default, one retry layer

Tokens

  • HS256 access JWT, 15 minutes
  • Refresh tokens hashed, rotated on every use
  • Reuse revokes the whole family
  • No MapIdentityApi: our own issuer

Authorization

  • Fallback policy: authenticated
  • Four named policies, one per endpoint
  • Other customer's data → 404, not 403
  • 3 rate-limit policies; 429 before 401

Resilience

  • HybridCache + Valkey: products only
  • Valkey down → no 5xx
  • EF retry is the only DB retry layer
  • Circuit breaker → 503 fast; OpenTelemetry

BFF · SINGLE-FLIGHT REFRESH

20 parallel requests, exactly one refresh

The hazard

  • Refresh tokens rotate; a second use = theft
  • Token expiring → 20 requests each refresh
  • API revokes the family → user signed out
  • Retrying a refresh is just as dangerous
private readonly ConcurrentDictionary<string,
    Lazy<Task<RefreshOutcome>>> inflight = new();

Lazy<Task<RefreshOutcome>> flight =
    inflight.GetOrAdd(sessionId, candidate);

// Only this caller's wait is cancellable.
// The refresh itself keeps running.
return await flight.Value.WaitAsync(ct);
One flight per session · no retry · never cancelled by a browser abort

BFF · PROXY & HARDENING

YARP allow-list, CSRF, CSP, rate limits, traces

YARP proxy

  • Explicit routes and methods from the endpoint catalog
  • Unknown path → 404, never index.html
  • Login / refresh / logout never proxied
  • Strip browser Cookie, add Authorization: Bearer
  • Strip upstream Set-Cookie

Browser-facing defenses

  • CSRF: X-CSRF: 1 + matching Origin
  • CSP script-src 'self', frame-ancestors none
  • nosniff, no-referrer, Permissions-Policy
  • Per-IP rate limits: 10 / min auth, 30 / min refresh
  • traceparent forwarded: one trace, BFF to API
